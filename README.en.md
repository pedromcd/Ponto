# ⏱️ Ponto Facial — Public demo

**A web-based time-and-attendance system with hour calculation, auditable corrections, and monthly closing, built with Python, FastAPI, SQLite, Jinja2, and OpenPyXL.**

> **Scope of this version:** the original system was designed to record attendance through **facial recognition**. The biometric code and employee data are **not part** of this release. This version demonstrates the administrative workflows using entirely fictitious data. **It is not a certified Brazilian time-recording system (REP-P) and must not be used as an official record of working hours.**

---

## 🎯 Goal

In small companies, attendance is often tracked on paper or in spreadsheets, and closing the month becomes manual work: adding up hours, finding missing punches, and fixing mistakes without losing the history.

This project automates that routine:

- records clock-ins and clock-outs;
- calculates daily worked hours and **flags inconsistencies** (for example, a clock-in with no clock-out);
- lets an administrator **correct** punches without deleting anything, keeping the reason and the person responsible;
- produces the **monthly closing** per employee and exports it to **Excel and CSV**.

---

## ✨ Features

- **Employees:** registration with name and department, and deactivation without deleting history.
- **Daily view:** the day's punches and computed hours for each employee.
- **Monthly closing:** a monthly summary per employee, with a day-by-day breakdown.
- **Manual punch:** records a forgotten clock-in or clock-out, always with a **reason** and the **person responsible**.
- **Dismiss a punch:** a wrong punch is flagged as ignored, with a reason and the person responsible. **The original record is never deleted**, which preserves the audit trail.
- **Pending days:** days with a clock-in and no clock-out (or vice versa) are flagged in the closing.
- **Export** of the month to **CSV** and **Excel (.xlsx)**.
- **Demo data** generated by a script, with no camera and no biometrics.
- **Write operations protected** by a token outside demo mode.

The interface and routes are in Portuguese.

## ⚙️ How it works

### Hour calculation

The day's valid punches (the ones not dismissed) are walked in chronological order and paired as **clock-in → clock-out**:

```text
08:00 in  ─┐
12:00 out ─┘  4h00
13:00 in  ─┐
17:30 out ─┘  4h30
              ─────
              8h30  (no pending issue)
```

If there are two clock-ins in a row, a clock-out with no clock-in, or a clock-in with no clock-out at the end of the day, the day is flagged as **pending** for review instead of silently producing a wrong number of hours.

### Data model

```text
employees(id, name, department, active)

punches(id, employee_id, occurred_at, kind ∈ {entrada, saida},
        source ∈ {demo, manual}, reason, actor,
        ignored, ignored_reason, ignored_by)
```

- `kind`: `entrada` = clock-in, `saida` = clock-out.
- `source` distinguishes automatic punches from manual ones.
- `reason`/`actor` record who made a manual correction and why.
- `ignored`/`ignored_reason`/`ignored_by` implement the auditable dismissal.
- An index on `(employee_id, occurred_at)` speeds up daily and monthly queries.

### Routes

| Method | Route | Description |
|---|---|---|
| `GET` | `/` | Home page |
| `GET` | `/health` | Health check |
| `GET` / `POST` | `/funcionarios` | Lists and registers employees |
| `POST` | `/funcionarios/{id}/desativar` | Deactivates an employee |
| `GET` | `/diario?day=YYYY-MM-DD` | Daily view |
| `GET` | `/fechamento?month=YYYY-MM` | Monthly closing |
| `GET` | `/fechamento/{id}?month=YYYY-MM` | Detailed closing for one employee |
| `POST` | `/marcacoes` | Manual punch (reason and person responsible required) |
| `POST` | `/marcacoes/{id}/desconsiderar` | Dismisses a punch in an auditable way |
| `GET` | `/exportar.csv?month=YYYY-MM` | Exports the month to CSV |
| `GET` | `/exportar.xlsx?month=YYYY-MM` | Exports the month to Excel |

## ▶️ Running it

Python 3.10+:

```bash
git clone https://github.com/pedromcd/Ponto.git
cd Ponto
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Enable demo mode, generate the fictitious data, and start the server:

```powershell
# Windows PowerShell
$env:PONTO_DEMO="1"
$env:PONTO_DB="data/demo.db"
python semear.py
uvicorn app.main:app --reload
```

```bash
# Linux/macOS
export PONTO_DEMO=1
export PONTO_DB=data/demo.db
python semear.py
uvicorn app.main:app --reload
```

Open `http://127.0.0.1:8000/fechamento` (monthly closing). `/funcionarios` (employees), `/diario` (daily view), and `/health` are also available.

## ✅ Tests

```bash
pip install -r requirements-dev.txt
pytest -q
```

The tests cover the health check, employee registration and deactivation, manual punches with export, rejection of invalid corrections, and the admin-token requirement outside demo mode. They run automatically on GitHub Actions.

## 🔒 Security and privacy

- Do not publish `data/*.db`, face models, employee images, credentials, exports, or backups.
- With `PONTO_DEMO=1`, all administrative operations are intentionally open for local testing. **Do not expose this mode to the internet.**
- Outside demo mode, writes and exports require the `X-Admin-Token` header, configured through `PONTO_ADMIN_TOKEN`. Read-only pages remain accessible, so the project must not be hosted with real personal data.

## ⚠️ Known limitations

- No camera or facial recognition in this public version.
- Hours are calculated from clock-in/clock-out pairs; contractual schedules, holidays, pay premiums, and labor rules are not interpreted.
- Days without punches are not automatically classified as absences.
- No user or role management, CSRF protection, complete access control, or immutable audit trail.
